# 上传耗时测量

R9 当前只做本地埋点和回归，未发布、未进行生产采样或上传架构优化。

计时使用 `System.nanoTime()`，日志固定为 `upload_timing stage=<固定阶段> elapsed_ms=<毫秒> bytes=<字节数>`。阶段只接受枚举，不能传入文件名、用户 ID、地址、签名或异常。失败路径也记录耗时，不吞掉原异常、不重试上传。

| 阶段 | 测量范围 | 限制 |
| --- | --- | --- |
| RECEIVE_LOCAL | MultipartFile 写入 SDK 所需临时文件 | Servlet 已解析 multipart，不包含浏览器到服务器的网络传输 |
| RECEIVE_REMOTE | 服务端下载远程图片 | 失败时尚无完整文件，bytes 记 0，不代表未收过数据 |
| PREPARE_VARIANTS | 准备数据万象变体规则 | 不是云端压缩时间 |
| COS_UPLOAD | 每次 SDK putObject 调用 | 图片 PUT 含云端变体生成；含 SDK 内部重试，不拆解单次 HTTP 尝试 |
| PRIVATE_ACL | 每个预期私有派生对象的 ACL 确认 | 不含 PUT；bytes 为该变体大小 |
| DATABASE | 公共落库事务、私有 save 调用 | 含权限复查和事务内清理队列操作；私有失败时还含补偿登记；bytes 为入库展示图 picSize，可能小于原文件 |

当前上传把原图和数据万象规则放在同一次 COS PUT 中，云端生成展示图和缩略图。没有独立的本地压缩或逐变体 PUT；不能拆出不存在的独立耗时，也不能据此直接实施“多个变体并行上传”。M-4 已确认 CosManager 和既有落库方法的计时修改范围，以上阶段已接入，不改变业务返回值和异常行为。

待授权部署后，在真实站点按顺序上传约 200KB 和约 2MB 图片各三次，记录每次端到端耗时、上述可测阶段及文件大小，整理到状态文件。以顺序、日志时间和线程辅助关联样本；计时本身不增加关联 ID，并发请求交错时不能可靠关联，应重新顺序采样。尚无生产测量结果，不从模拟测试推断性能改善。

本地验证（2026-10-31）：`mvn verify` 515 项，510 通过、5 条件跳过；新增 13 项覆盖日志格式及输入大小、失败接收、五种 COS 调用入口、私有 ACL 和公共/私有保存的成功与异常行为。前端单测 166 项、完整浏览器回归 104 项、类型检查、生产构建均通过，Gitleaks 工作区和历史扫描通过。测试没有连接生产桶或数据库。
